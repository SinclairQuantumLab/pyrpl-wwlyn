# Native uv project migration

This non-hardware packaging change completes the repository's intended uv
project conversion without carrying forward the placeholder metadata and
incorrect source layout from commit `fcd94a0`.

## Project metadata

- `pyproject.toml` is the sole package and dependency metadata source.
- The distribution and import package remain `pyrpl`, version `0.9.5.0`.
- CPython support remains bounded to `>=3.14,<3.15`.
- Runtime bounds are unchanged from the field-preparation branch.
- The `test` extra retains ipykernel and Nose NG and now includes the coverage
  dependency already enabled by `setup.cfg`.
- The flat, existing `pyrpl/` package layout is declared explicitly for
  `uv_build`; no generated `src/pyrpl_change` package is introduced.
- `uv.lock` is generated by uv and committed for reproducible `uv sync` and
  `uv run` workflows.
- The obsolete `setup.py` and one-line `requirements.txt` compatibility shim
  are removed. Active installation, test, server-build, and distribution
  documentation now uses uv or the underlying tool directly.
- The Azure pipeline now exercises only the supported CPython 3.14 target and
  the repository's hardware-safe offline suites through the locked uv
  environment.

## Preserved package payload

The wheel must retain the Python packages and the same top-level package data
previously selected by setuptools, including the fork FPGA BIN, configuration
files, GUI images, and monitor server files. FPGA implementation
sources and reports remain in the source distribution but are excluded from
the wheel, matching the earlier wheel's scope. The Gen 1/OS 1 source contains
no DTBO, and this packaging change does not add one.

## Validation requirements

- `uv lock --check` and `uv sync --locked --extra test`;
- compile every tracked Python file;
- the safe Nose NG and unittest compatibility suites in `AGENTS.md`;
- a clean `uv build --no-sources` followed by wheel inventory and installation
  into a fresh Python 3.14 environment;
- distribution/runtime version agreement and console-entry-point smoke tests;
- the exact fork FPGA BIN hash and absence of any DTBO.

No live-device access or FPGA build is part of this migration.

## Validation evidence

Validated on CPython 3.14.4 with uv 0.12.0:

- `uv lock --check` and `uv sync --locked --extra test` succeeded;
- compilation of the package, regression tests, and documentation Python
  sources succeeded;
- 9 Python 3.14/ipykernel compatibility tests passed;
- 17 safe Nose NG tests passed and produced the configured XML coverage and
  xUnit reports;
- `uv build --no-sources` produced both the source distribution and a wheel,
  building the wheel back from the source distribution;
- the wheel contains the same 124 non-metadata files as the preceding
  setuptools wheel, with no filename or content-hash differences;
- a fresh CPython 3.14 environment installed the wheel and its 63 runtime
  dependencies, and `uv pip check`, package import, version metadata, and the
  `pyrpl --help` entry point all succeeded;
- the installed wheel contains both precompiled monitor servers, the exact
  approved fork BIN, and no DTBO.

qasync 0.28 emits its known Python 3.14 deprecation warning for
`asyncio.iscoroutinefunction`; all event-loop regressions nevertheless pass.
No Red Pitaya was contacted during validation.
